# Q7 Scoping — Optional Recovery/Healing Phase (SIR-style variant)

**Status:** design document only (no implementation). Produced for queue task M on 2026-07-04.
**Research question affected:** **Q7** (okf/open-questions.md; D-028 track 4, explicitly lower-priority): *optional recovery/healing phase (SIR-style) as a model variant, vs. the current permanent-activation assumption.*
**Reader contract:** self-contained; §N labels refer to the migrated tracker sections in `okf/`. Priority framing up front: per D-028 and §6, this is **pure stretch** — nothing here is MVP-adjacent (§3 below makes that precise).

---

## 1. What changes, precisely — two variants, not one

The frozen model (§3.1/§3.4): failure is **absorbing**; the process halts at the first quiet round, and the absorbing state is genuine because $g_{t+1}=0$ after a quiet round. "Adding recovery" hides a fork that must be chosen deliberately, because the two branches have qualitatively different dynamics:

**Variant R1 — SIR-immune (recommended first; closest to D-028's "SIR-style").** States Solvent → Failed → **Recovered**, with Recovered absorbing: a failed bank recovers with per-round probability $\rho$ (geometric sojourn, memoryless — the natural first choice; a fixed deterministic sojourn $\tau_{\mathrm{rec}}$ is the obvious robustness variant), becomes *immune* (never fails again, through either channel), and **stops counting as failed for its neighbors' solvency thresholds** (economic reading: a resolved/recapitalized bank no longer transmits counterparty losses). $\rho=0$ recovers the frozen model exactly.

**Variant R2 — SIS-resusceptible (the deeper change; second phase only).** Failed → Solvent again, re-eligible for both channels, counters recomputed. This is the variant the task plan's wording gestures at; it is *much* more invasive: failure events can recur indefinitely, an endemic (non-halting) phase becomes possible, and the "final failed fraction" stops being well-defined. Scope R2 out of the first implementation; this doc specs its stopping rule anyway (§2) so the fork is documented, not forgotten.

**State/counter semantics (both variants — the details that make or break parity):**
- The solvency rule (§3.2) is reinterpreted as counting **currently-failed** neighbors: when bank $j$ recovers, every neighbor's `failed_neighbor_count` is decremented. (The alternative — counting ever-failed neighbors — makes recovery cosmetic for the solvency channel and is not what "healing" means economically.)
- The fear field stays $g_t = a_{t-1}/n$ with $a_{t-1}$ = **new failure events** in round $t-1$ (D-005's incremental field, unchanged; recoveries do not subtract from $g_t$ — panic responds to fresh failures, and negative fear is meaningless).
- Update order within a round (simultaneity, §3.4 discipline): evaluate all failures against the start-of-round snapshot, evaluate all recoveries against the same snapshot ($\rho$-coin per currently-failed bank), then apply both. A bank cannot fail and recover in the same round. $f_i$ is drawn once and kept (heterogeneity is a trait, not a state) — R2 re-failures reuse the same $f_i$.

## 2. What breaks: halting, and the honest answer on oscillation

**R1 halts genuinely.** Every node ends Solvent-never-failed or Recovered (failed banks leave the F state at geometric rate). Halting rule: **stop when the currently-failed set is empty** ($F_t=\varnothing$). This is a true absorbing state: no failed banks ⇒ no solvency pressure and $g_{t+1}=0$ next round after a quiet one — the §3.4 argument survives with "quiet round" replaced by "empty failed set." Termination is a.s. and in expected $O(\log n/\rho)$ extra rounds after the last new failure. **The order parameter must change:** the systemic event becomes $|\mathcal E^*|/n \ge \theta$ where $\mathcal E^*$ = **ever-failed set** (equivalently Recovered ∪ currently-failed at halt); the final *currently*-failed fraction is always 0 and carries no information. Secondary observable worth recording: **peak prevalence** $\max_t |F_t|/n$ (the "how bad did the crisis get at once" number — new to this variant and economically interesting).

**R2 can oscillate — named, not glossed.** With re-susceptibility the only absorbing state is all-solvent; a solvency-sustained endemic regime is a real possibility (failed cores maintaining $\ge r$ pressure on recycling neighbors). The process is a finite Markov chain whose only absorbing state is all-solvent, so extinction is *eventually* certain — but the expected extinction time can be exponential in $n$ (quasi-stationarity), which for simulation purposes *is* non-halting. Stopping rule for R2, fully specified: halt at $F_t=\varnothing$ (true extinction) **or** at a hard horizon $T_{\max} = C\,n$ rounds (working $C=10$); on horizon exit, classify the run **endemic** and record the trailing-window mean prevalence $\bar F = \frac{1}{W}\sum_{t=T_{\max}-W}^{T_{\max}}|F_t|/n$ ($W=100$). R2's phase diagram therefore has *three* outcomes (extinct-small / extinct-systemic-ever / endemic) — a genuinely different object from the frozen model's two-phase diagram. This is the core reason R2 is second-phase.

**Subcriticality of fear under recovery — worked out, not assumed (DoD item).** The §3.3 invariant is $R_{\mathrm{fear}}\approx\mu<1$: one failure event generates $\approx\mu$ expected fear-failures next round. With recovery: expected fear events in round $t$ are $g_t\sum_{i\,\text{solvent}(t)} f_i = \frac{a_{t-1}}{n}\sum_{i\in S_t} f_i \le \mu\,a_{t-1}$, with equality approached as the solvent pool refills. Recovery only ever *moves banks into* the solvent pool, so it pushes the inequality **toward** its ceiling $\mu\,a_{t-1}$ but can never exceed it — and in R1 immunity removes ever-failed banks from the susceptible pool entirely, making the effective offspring *strictly smaller* than in the frozen model. **Conclusion: $R_{\mathrm{fear}}\le\mu<1$ survives in both variants; fear alone still cannot ignite or sustain a cascade, and in R2 fear alone cannot sustain an endemic state either** (per-event offspring mean $<1$ regardless of susceptible replenishment — replenishment raises the pool toward $n$ but the field normalization by $n$ already assumed that). What recovery *does* change is the **solvency** channel's arithmetic: counters now decrease, so the cascade must outrun healing — that race is the whole physics of Q7.

## 3. North Star reconciliation — plainly

This variant **does not change the paper's central claim** (§2: the $(r,\mu)$ systemic-event phase diagram under the self-referential fear field with permanent failure). R1 *extends* the diagram with a third axis $\rho$, and $\rho=0$ is the frozen model on the boundary of that axis. It is a robustness/extension chapter ("does the two-channel boundary survive healing, and how does it move?"), not a revision of the core object — consistent with §6 already bracketing it as low-priority stretch and D-028 listing it fourth of five. If simulations ever showed the $\rho\to0$ limit to be *discontinuous* (the diagram jumping as infinitesimal healing is switched on), that would be a finding that reflects on the frozen model's robustness and should go straight to Gary — flagged here as the one scenario that would promote Q7 from stretch to load-bearing. No frozen text changes now; adopting R1 into the model spec would need its own decision entry (d-031+).

## 4. Falsifiable conjecture (C-Q7)

The mechanism: near the critical seed, the frozen cascade's early generations grow *slowly* (the §4 saddle-node bottleneck), so even weak healing should kill marginal cascades — recovery is maximally effective exactly at the boundary. Hence:

> **C-Q7 (healing shifts the boundary monotonically and closes the systemic phase at a finite threshold).** Fix $r=2$, $\kappa=50$, $\theta=0.5$ (systemic = ever-failed fraction $\ge\theta$), variant R1.
> **(i) Monotone boundary shift.** $P(\text{systemic})$ is non-increasing in $\rho$ at every $(\mu,a)$ cell, and the empirical critical seed $a_c(\mu,\rho)$ is strictly increasing in $\rho$.
> **(ii) Finite closing threshold.** There is $\rho^\ast(\mu, np) < \infty$ such that for $\rho > \rho^\ast$ the systemic phase is empty for all seeds $a=o(n)$ — no sub-linear shock can reach $\theta n$ ever-failed, however placed. (Heuristic anchor: the frozen near-critical growth rate per round is finite and $O(1)$ at the bottleneck; once the per-round removal rate $\rho$ exceeds it, the failed set's drift is negative uniformly near the tangency point.)
> **(iii) Divergence form.** Approaching the threshold from below, $a_c(\mu,\rho)/a_c(\mu,0) \sim (1-\rho/\rho^\ast)^{-\xi}$ for some $\xi>0$ — the pre-registered scaling ansatz to fit or refute (refuted e.g. by a finite jump of $a_c$ at $\rho^\ast$, i.e. a first-order closing).
> **(iv) Fear–healing interaction (the two-channel-specific clause).** $\rho^\ast$ is increasing in $\mu$ — fear, by adding round-rate to the cascade, buys headroom against healing — and the iso-boundary surfaces in $(\mu,\rho)$ at fixed $a/a_c(0,0)$ are monotone curves (no re-entrant systemic region). Refuted by any non-monotonicity beyond MC error.

All four clauses are readouts of $P(\text{systemic-ever})$ grids over $(\mu,\rho,a)$ plus the existing crossing-interpolation machinery (`analysis.py`, D-021 clamping unchanged). The $\rho=0$ column doubles as the regression control against the frozen model.

## 5. Implementation plan (per `AGENTS.md` §IV convention)

**Oracle protection governs the design (task watch-out, honored structurally).** Recovery cannot be a `reference.py` edit — not as a flag, not as a default-off parameter — without a standalone, explicitly-approved instruction (§III oracle rule; D-026 is the precedent for how even additive changes must be handled). **This design requires no such approval,** because it puts the variant in its own module:

- `src/twocascade/recovery.py` (new): `run_cascade_sir(adjacency, nodes, r, seed_indices, rng, recovery_rng, rho, record_history, window_len, weights) -> RecoveryCascadeResult` — mirrors `run_cascade`'s two-phase evaluate-then-apply structure (LESSONS §2 "Simultaneous Update Parity": failures *and* recoveries judged against the frozen start-of-round snapshot), with per-neighbor counter decrements on recovery and the ever-failed/peak-prevalence bookkeeping of §2. `RecoveryCascadeResult` adds `ever_failed_fraction`, `peak_prevalence`, `recovered_total`.
  - **The $\rho=0$ exactness trick:** recovery coin-flips consume a **separate RNG stream** (`recovery_rng`, its own `SeedSequence` child). At $\rho=0$ zero recovery draws are taken, the main stream's draw order is untouched, and `run_cascade_sir(..., rho=0)` must produce **bit-identical trajectories to the oracle's `run_cascade`** on the same graph/fears/seeds/main-stream. That exact-equality test is the variant's §5.4-style validation prong A, and it is only possible because of the split stream — single-stream designs would desynchronize draw order and downgrade the check to statistical. (LESSONS §1 seeding discipline applies as usual: spawned children, never additive offsets.)
- `runner.py`: additive config key `"recovery": {"rho": ...}` routing to the variant engine; absent key → existing oracle path byte-identical. Raw output schema gains the two new observables; the systemic metric name in outputs must say `ever_failed` explicitly so old and new fractions are never silently conflated in analysis.
- **C++ parity: explicitly out of scope until the Python variant has results** (this is the §IV parity-scope statement). If promoted: the engine change is small (state enum + counter decrements + second RNG), prong A carries over as the same-graph $\mu=0,\rho>0$ deterministic-given-draws check is *not* available (recovery is stochastic even at $\mu=0$), so the C++ prongs become: $\rho=0$ exact-match against its own frozen path, plus D-024 p-value statistical agreement on $(\mu,\rho)$ cells for `ever_failed_fraction` and `peak_prevalence`.
- **R2 (SIS)** would add `run_cascade_sis` with the §2 horizon/endemic classification — deliberately not scheduled; revisit only if R1 produces something worth deepening.
- Compute note: R1 runs are at most modestly longer than frozen runs (recovery shortens cascades if anything); the $(\mu,\rho,a)$ grid is one extra axis — keep the first sweep at a single $n$ (2000) and a coarse $\rho$ ladder $\{0, 0.02, 0.05, 0.1, 0.2, 0.5\}$ before any finite-size ambitions.

## 6. Risks

- **Trivial-outcome risk:** recovery might simply rescale time (cascades slightly slower, boundary barely moves) until an abrupt cutoff — i.e. clause (iii)'s $\xi$ ill-defined because the transition in $\rho$ is first-order. That is still a clean result (the systemic phase is *robust* to healing up to a sharp threshold — arguably the more interesting headline); pre-commit to reporting whichever shape appears, no parameter-fishing.
- **Metric confusion risk:** ever-failed vs currently-failed vs peak — three fractions now coexist; the §5 schema naming rule exists to prevent a silent apples-to-oranges plot (this is the kind of wording slip S-006/S-007 errata were needed for; cheaper to prevent).
- **Comparability risk:** $a_c$ multiples must stay referenced to the frozen $a_c(\mu,\rho{=}0)$ so the $\rho$ axis measures healing, not a moving baseline.
- **Scope risk:** R2's endemic phase is a rabbit hole (quasi-stationary analysis, horizon sensitivity). The R1-first sequencing and the hard $T_{\max}$ rule are the guardrails.

## 7. Summary judgment

Q7 is well-posed, cheap to pilot (one new module + one config key + a $\rho$ ladder at $n=2000$), and safely additive: it needs no oracle change, no frozen edits, and its $\rho=0$ limit is an exact regression test. It stays pure stretch — schedule behind Q4/Q5 (which the advisor prioritized and which feed the 2026-07-15 meeting), and promote only on either a positive C-Q7(iv) interaction result or the §3 discontinuity surprise.
