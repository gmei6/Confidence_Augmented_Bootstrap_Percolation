# Lessons Learned (agent memory)

This file records codebase-specific gotchas, performance constraints, and modeling discoveries to prevent future agents from repeating past errors. **Read this file before starting any planning phase.**

---

## 1. Mathematical & Simulation Pitfalls

*   **Beta Distribution Concentration:** When setting individual fear distributions, use the Beta distribution concentration $\kappa$ to tune variance. Avoid truncated normal distributions because their realized mean departs from $\mu$ near boundary values.
*   **Subcriticality of Fear:** Keep in mind that $R_{\text{fear}} \approx \mu < 1$. Fear acts as an amplifier, not a primary igniter. The cascade requires a macroscopic seed to cross the saddle-node tangency point.
*   **Janson Scaling Regime:** Connectivity $p$ must scale as $p_n = \beta n^{-\alpha}$ where $\alpha \in (1/r, 1)$. Never hold $p$ constant when changing $n$ in finite-size sweeps, as it destroys the threshold scaling invariants.
*   **RNG Seeding in Multiprocessing:** When parallelizing sweeps, use `numpy.random.SeedSequence.spawn` rather than simple increments or thread-shared generators to avoid correlated random streams across worker processes.
*   **Avoid Float Dictionary Keys:** In numerical sweeps, avoid indexing dictionaries directly via float parameter keys (e.g. `0.3`), which are vulnerable to representation variance. Instead, stamp results with their grid coordinate integer indexes (`mean_fear_idx`) in the sweep runner.
*   **RNG Seeding Chain:** Avoid using simple `base_seed + trial_index` additions for thread seeding to prevent RNG stream correlation across cells in grid sweeps. Mix the base seed first using a hash (like `SplitMix64`) before adding the trial index.
*   **Near-Floor Quantization Error:** When empirical thresholds (`a_emp`) approach within 1–2 discrete grid points of the absolute floor (`min_seed_size`), statistical deviation metrics skew upwards. These are artifacts of grid spacing constraints rather than scaling law violations. Future validation tracks should incorporate variance-weighted aggregates or assign explicit low-confidence flags to high-mu rows approaching boundary thresholds.
*   **Conflating Finite-Size Inflation with Quantization Error:** Do not misattribute systematic scaling biases to physical seed-size floor constraints (quantization error) unless the data is genuinely clamped near the absolute minimum ($a \ge r$). A $\mu$-dependent residual of the finite-size inflation factor $K(\mu, n)$ can cause systematic biases well above the floor.
*   **Janson $a_c$ Does Not Transfer to Heavy-Tailed Configuration Models:** Seed grids built as multiples of the $G(n,p)$ Janson $a_c$ are entirely supercritical on a $\tau=2.5$ CM — the real ignition transition sits near $a \in [2, 32]$ at $n=4000$, two orders below. Always pilot the transition location with tiny seeds before committing a sweep grid on a new graph family.
*   **$\varepsilon$-Cap Breaks Equal-Total-Fear for Positive Tilts:** At $\tau=2.5$, `sample_degree_dependent_fears` with $\gamma=+1$ hits the $1-\varepsilon$ cap at every $\bar\mu \ge 0.1$ (realized $\bar\mu$ shortfall 6–28%), because $Z_n$ normalizes pre-cap. Any cross-$\gamma$ comparison must first check `stats["realized_mu_bar"]` against nominal; treat cap-affected cells as artifact-suspect, never as conjecture refutations. **Fixed S-054** via iterative water-filling (renormalize $Z_n$ over uncapped nodes only, repeat to a fixed point) — see the three follow-on lessons below from that fix's `/verify` gate.
*   **Cap-Aware Redistribution Needs a Provable Iteration Bound, Not a Guessed One:** When iteratively renormalizing a capped population mean, bound the loop by a proven invariant (e.g. "capped-set membership is monotone non-decreasing in the rescale factor, so it stabilizes within $n+1$ steps"), not a round guess like 50 — a guessed bound can silently return a non-converged result on a large-$n$ production config while looking fine on small test cases. Prefer a hard `raise` on exceeding the *proven* bound (that means a real bug) over a soft flag.
*   **A Placeholder Value for a Non-Finite Weight Must Be Excluded From Every Re-Test, Not Just the Initial Seed:** Handling a non-finite input (e.g. a zero-degree node under a negative tilt exponent, giving weight $=\infty$) by substituting a placeholder (e.g. $0$) and seeding it into a "forced" set is not enough — if the loop re-derives set membership each round by re-testing the placeholder value, the node can flip back out the moment the recurrence runs, silently inverting the intended extreme-case behavior (an isolated node under negative tilt should get the *highest* fear, not the *lowest*). OR the non-finite mask into the membership test unconditionally every iteration, not just at initialization. Caught by two independent blind reviewer rounds during S-054's `/verify` gate, invisible to aggregate-only checks (the population mean still looked correct).
*   **One "Degenerate" Flag Covering Two Different Guarantees Will Mislead Callers:** If a function can fail to meet its target for two structurally different reasons (e.g. the target is truly infeasible under the input shape, vs. a defensively-handled edge-case input that doesn't actually compromise the result), collapsing both into one boolean lets a caller who checks it before trusting an aggregate statistic be wrong half the time. Split the flag so exactly one sub-flag is the "the aggregate may be wrong" signal, and document which one. Also: an early-return special case (e.g. a trivial `target==0` shortcut) must run *before* any diagnostic stats are computed from the general-case path, or the returned stats can describe an intermediate computation the actual output doesn't reflect.
*   **The $a \ge r$ Floor Is a $\mu=0$ Theorem, Not a Model Invariant (S-064, D-043):** with fear active, a fear-channel failure can supply the second failed neighbour the $r=2$ rule needs, so ignition from a single seed has strictly positive probability — measured at rate $\approx 1-e^{-\bar\mu}$, essentially independent of $\langle k\rangle$ and $n$ (the round-1 expectation $n\cdot\bar\mu\cdot(1/n)$ cancels the $n$). The floor is exact only at $\mu=0$ (18,000/18,000 control trials halt at $|A^*|=1$). Do not apply floor-based exclusions or near-floor caveats to $\bar\mu>0$ measurements without this qualification.
*   **Same-Round Nucleus Counts Understate Remote Ignition:** `remote_nucleation` clusters one round's remote failures, but `failed_neighbor_count` is cumulative and failures are permanent, so two lone remote fear failures in the same ball in *different* rounds also ignite at $r=2$. Slope tests on per-round nucleus counts conflate this with front-perimeter kinematics (for a 2D ballistic front, new $\propto \sqrt{g}$); prefer a remote-ignited-growth tracker, and if fitting rates, fit against the windowed drive $\varphi_t$ the engine actually uses, not cumulative $g_t$.

## 2. C++ & Performance Pitfalls

*   **Adjacency Representation:** Never materialize dense $n \times n$ adjacency matrices. Always use CSR (Compressed Sparse Row) or light coordinate lists for graph operations.
*   **Random Number Generation:** Cross-validation between Python and C++ must not rely on bitwise RNG stream agreement. Instead, validate via same-graph static runs at $\mu=0$ (exact parity of failed sets) and statistical distributions for $\mu>0$.
*   **Calibrate Cross-Language Parity Thresholds by p-value, Not Fixed Distance:** A fixed two-sample KS *distance* cutoff (e.g. `< 0.05`) is sample-size-dependent and can sit *below* the test's own critical value — at $N=1000$/engine the 5% KS critical value is $\approx 0.061$, so a 0.05 cutoff false-rejects $\approx 16\%$ of the time per check ($\approx 50\%$ across 4 parameterized cells) even when the engines are identical. This manufactures spurious "divergences" and tempts seed-shopping. Use a scale-invariant **p-value** threshold matching the z-test significance (e.g. `p > 0.005`), pair it with a single documented seed on both sides, and confirm via a multi-seed diagnostic (or grand-mean comparison) that genuine parity passes comfortably. The fix is recalibrating the test, never hunting for a seed that passes.
*   **Dynamic Multiprocessing Chunksize:** Grouping tasks using a static `chunksize` can leave workers idle on small sweeps. Dynamically compute the chunksize as `max(1, len(tasks) // (n_workers * 4))`.
*   **C++ Beta Distribution:** `<random>` lacks a native `std::beta_distribution`. Implement manually using Gamma variables ($Z = Y_1 / (Y_1 + Y_2)$) and write guards to prevent undefined C++ behavior if Gamma shape parameters are zero (e.g., at $\mu=0.0$ and $\mu=1.0$).
*   **C++ Compiler Flag Rosetta Conflict:** On Apple Silicon M-series Macs, compiling with an x86_64 target toolchain (e.g. `cmake` installed via x86_64 Homebrew) causes `-march=native` to fail during code generation since the host CPU is detected as `apple-m1`. Use CMake feature-testing dispatch targeting the specific architecture (e.g. check for `-mcpu=native` on Apple, and fallback to `-march=native` elsewhere) and compile with `-DCMAKE_OSX_ARCHITECTURES=arm64` to target ARM64 natively.
*   **Simultaneous Update Parity:** To maintain parity with simultaneous updates, separate evaluation scans from state mutations (flags and neighbor counters must remain frozen until the end of the round). Active lists can be updated in-place at the end of the round using `std::remove_if`.

## 3. Workflow & Tooling Pitfalls

*   **Oracle Protection:** `src/twocascade/reference.py` is the unassailable oracle. Do not edit it as a side-effect of C++ work; any changes require a dedicated and approved plan.
*   **Running Results:** Never write simulation outputs directly to `results/raw/` or `results/figures/`. They must always be written by a runner script that logs the seed, parameters, and commit hash.
*   **Rosetta Python vs arm64 numpy (this machine):** the default `/usr/local/bin/python3` shell launch runs x86_64 under Rosetta while site-packages numpy is arm64, producing `ImportError: incompatible architecture`. Run simulations with `arch -arm64 python3` (or `/opt/miniconda3/bin/python3`). This was the "missing numpy" that blocked Task H in S-044.
*   **Figure Functions Must End With savefig/close — and "Done!" Doesn't Prove a File Was Written:** `plot_fear_field_concentration` in `src/twocascade/plotting.py` builds its figure and returns without ever calling `plt.savefig`/`plt.close`, so `scripts/run_task_e.py` prints "Done!" while the relvar figure is silently never (re)written (caught in S-048 because the on-disk PNG's mtime predated the regen). When verifying a pipeline, check output-file mtimes/content against the run, not the script's success message; and every plotting function must end with an explicit `savefig` + `close` pair.
*   **A Missing Report File Does Not Mean a Task Is Open (S-058):** task closure in this repo is recorded in **commit bodies** and `okf/changes/`, not reliably in `docs/queue/reports/`. Tasks V/W/U were fully `/verify`-cleared with AUDIT PASS recorded *only* in `d70dbd8`'s commit body — no report files, no `okf/status.md` entries. Inferring "no report ⇒ not closed" produced a session of redundant work re-deriving already-verified results, and nearly shipped a report whose Task W section was backwards relative to an existing gated verdict. Before declaring anything open, read `git log -1 --format=%B <commit>` — **not** `--oneline`, which truncates exactly the body where the gate result lives.
*   **Live Notes Drift Toward the Last Exciting Hypothesis, Not the Last Verified Result (S-058):** `okf/next-actions.md` carried a "shared n≈20000 crossover" framing as advisor-worthy *after* Task W had tested and refuted it, alongside superseded Q3 ν values and a retracted flattening reading. The statistics had been computed and committed; only the prose was never updated. When a task's verdict contradicts the observation that motivated it, the motivating text needs an **explicit retraction** — it will otherwise survive into outward-facing material (here, three days from an advisor meeting). Corollary: when correcting an auditable report that was accurate when written, **append a SUPERSEDED note rather than editing the original sentence** — rewriting history destroys the audit trail of what was known at the time.
*   **A Mechanism Claim Needs Its Own Check, Separate From the Observation That Prompted It (S-058):** twice in one session an agent paired a *correct* observation with an *invented* explanation, and stated both at the confidence the observation had earned. (i) "The handoff crossed its μ values" — the observation that a cited slope pair was imprecise was right; the mechanism was wrong (both figures were μ=0.2, correctly rounded; the actual flaw was not labelling *which* μ). (ii) "The table/figure gap at μ̄=0.4 is sampling variation across seeds" — the observation that two embedded artifacts disagreed by 28% at a cell was right and worth flagging; the mechanism was wrong, and would have shipped a **false statement**, because the μ=0 row reproduces all five cells *exactly* and sampling variation cannot do that. The real cause — Python-path seeds come from one flat `spawn(num_cells × trials_per_cell)` consumed cell-major, so widening a grid re-indexes later cells onto new streams while index 0 stays put — predicts **both** the exact match and the divergence from a single cause. **The tell in both cases:** reaching for the first explanation that fits the subset already examined. **The fix is not more vigilance** (naming the failure mode once did not prevent the repeat) but a structural habit: before a mechanism goes into a sentence, check it independently of the evidence that suggested it, and require it to predict *everything* observed — including the parts you did not look at. An explanation that only covers the cells you happened to print is a hypothesis, not a finding.
*   **Plain Language Is a Correctness Requirement, Not a Style Preference (S-058):** an explanation Gary cannot follow has failed, however accurate it is. In S-058 an agent explained a confound using unglossed experiment jargon — "arm", "the light-tail arm given the heavy arm's density", "finite-variance regime" — and Gary's response was *"I don't understand what you mean… I am beginning to believe continuing down this line is a waste of time."* The underlying content was two plain sentences: *changing τ changes two things at once (how concentrated the connections are, and how many there are in total); the second difference is far too small to explain the result.* **Rules:** gloss every term of art at first use, then keep using it — the failure is *unexplained* jargon, not jargon. Gary is a researcher who needs these words in the room with his advisor; stripping them out is its own failure mode, and he pushed back on that too ("I don't want the text to read like a middle-school explanation"). A metaphor is scaffolding: build the intuition, then name the real term and use it. Don't stack several undefined terms in one sentence. And when a table is meant to carry one number, cut every column that does not — an irrelevant n-scaling column in the same table sent Gary to the wrong reading of it entirely. Test: could he restate the point back? If not, the writing is wrong, not his reading.
*   **An Objection Must Be Stated Before It Is Defended (S-058):** it is right to raise a problem the human has not spotted — the τ/mean-degree confound was real and Gary explicitly endorsed raising it. What failed was the order. The agent named the confound in one compressed clause and then spent four rounds building a *defense* against it (Janson `a_c`, counterfactual densities, an ER-heuristic caveat), so Gary was reading the rebuttal to an objection he had never been given clearly. **Structure any objection as: (1) what you claimed, (2) what could be wrong with it, in one plain sentence, (3) how bad it is, (4) only then, what to do about it.** Do not begin defending until step 2 has visibly landed. Corollary on effort: an objection the reviewer has not raised is *insurance*; before elaborating it further, ask whether the elaboration is worth more than the human's remaining time — in S-058 it was not, and the agent should have said so before the fourth round rather than after Gary did.
*   **Label Computed Values as Computed, Especially Beside Measured Ones (S-058):** Gary read a table of Janson-formula predictions as simulation results — *"when testing, we determined"* — because the agent had presented derived numbers in the same visual register as measured ones. He was one sentence from telling an advisor that a counterfactual calculation was an experiment. Any artifact mixing the two must mark which is which inline (not in a distant caveat), and must state where a formula does **not** apply: the same table's authority rested on `a_c = n/(2d²)` being valid only for finite-variance degrees, i.e. *not* for the τ=2.5 arm — the very fact that made the argument work, and the one most easily lost.
*   **Curves Spliced From Different Calibration Eras Are Not One Comparison (S-064, D-042):** the famcompare CM curve was silently sourced from raws calibrated to mean degree 4.0 while the ER and GIRG curves it sat beside were matched at 4.533 — a 13% edge-probability difference that manufactured a consistent cross-family gap ("geometry damps fear") which vanished on matched data. Before combining or extending any curve from a second raw source, verify the FULL pinned-param set including the calibration target, and enforce it with a runtime check in the analysis script (fail loud, never splice silently). Corollary, S-058 family: a visually consistent gap whose per-cell CIs overlap is a hypothesis, not a claim — the CI-overlap caution flagged this exact sentence hours before the ensemble check killed it.
*   **Raw↔Config Self-Consistency Is Not Slot or Experiment Identity (S-066, M-4/M-5):** a provenance guard that derives each raw's config from its own basename and verifies the pair agree certifies only that the raw is *internally* consistent — it cannot detect the raw sitting in the wrong μ̄ slot of its own family, the wrong n slot, or being a *pilot* twin of the production raw (pilots share every pinned metadata key, their own committed config, the same graph block, and the same mean_fear cells; only `trials_per_cell` and the seed grid differ). A guard must bind **every axis that discriminates the intended experiment**: graph family, μ̄ slot (config grid AND cell-level), n slot, and trials count — and the trials pin needs both a relative (family-identity) and an absolute (==500) form, because the relative check alone accepts an all-pilot family. Demonstrated stakes: a μ̄=0 pilot substitution silently moved Q6's headline from +11.7% to +1.3% with `reliable=True`. Found only by adversarial replay across three blind critic rounds — each round's fix was real and each round still found a fresh hole in the same guard.
*   **A Deliverable Bundle Is an Output Too — Verify It Against Current Sources by Hash (S-066, M-2):** the Overleaf zip (and its `~/Downloads` copy) silently carried superseded figure panels and an old poster.tex while the repo's figures were current — nothing forces a bundle rebuild when `results/figures/` changes, and mtimes lie. Before any print/submit milestone, md5-compare every file inside the staged bundle against its live source; and after regenerating figures, treat every downstream copy (staging dirs, zips, synced folders) as stale until re-verified. Corollary from the same gate: emit a `provenance_certification` block in analysis artifacts so a guarded run is distinguishable from an unguarded one — a guard that leaves no trace in the output cannot be audited later.
*   **GitHub Actions Path Filters and Cleanup Commits:** If a commit deletes or reorganizes temp directories (e.g. `viz-temp/`, `temp_zip/`) without touching files under the `viz/**` path filter, the Pages deploy workflow will not trigger — even if the commit message says "updated viz." When a deploy appears stale after a cleanup commit, add a trivial change (e.g. a trailing newline in `viz/README.md`) to a file inside the watched path and push to force a re-trigger.

## 4. AI Studio Code Generation Pitfalls

*   **AI Studio defaults to React/Vite regardless of spec:** Even when a spec explicitly requires "pure static HTML + CSS + JS, no build step, no frameworks," AI Studio wraps the output in a React/Vite scaffold (`package.json`, `tsconfig.json`, `src/App.tsx`). The actual usable static files are typically in a subfolder. For future requests, add the explicit constraint: *"Do NOT use React, Vite, TypeScript, or any build tool. Output must be exactly three files: index.html, style.css, script.js. No package.json."*
*   **AI Studio `.env.example` and `@google/genai` are template noise:** The generated zip includes a `.env.example` with `GEMINI_API_KEY` and `@google/genai` in `package.json` regardless of whether the spec prohibits API usage. Verify by checking the static HTML's Network tab — no actual API call may be made even when the dependency is present.
*   **`fetch()`-based ZIP download buttons require a server:** A download button implemented with `fetch()` on local files works when served (`http://`) but silently fails from `file://`. For a purely local study page, either omit the button or replace it with a static link.

## 5. Multi-agent Orchestration & CLI Tooling

*   **Avoid Float Crossing Clamping**: When interpolating empirical thresholds, crossings that are stuck at the minimum sweep seed size are clamped floor points (lower bounds, not resolved crossings) under high fear. Check `a_emp > grid_floor` (inequality) rather than checking float equality to filter them out in validation plots.
*   **Runnable Plotting Entry Point**: Keep plotting modules executable as standalone CLI scripts (e.g. via `if __name__ == "__main__":`) so that figures can be automatically regenerated from raw results on disk, ensuring complete reproducibility.
*   **Metadata Provenance Decoupling**: Plotting scripts must never write or overwrite analytical data JSONs. Figure generation should strictly *read* analysis artifacts to prevent silently rewriting `analysis_runtime_commit` stamps and compromising provenance integrity.
*   **A selection rule can make a metric structurally tautological — check before reading a "negative" as physics (S-057, Task R):** the cross-round nucleus metric selected nodes for being > r_n from all prior failures, then asked whether they land within r_n of a prior failure — which is impossible *by construction*, forcing `round_gap=0` for every nucleus. The "no cross-round nucleation" result was a tautology of the measurement, not a physical finding. Before treating a null/negative result as evidence, verify it isn't forced by how the quantity is defined or selected. Corollary: **a matched null must enforce the SAME structural constraints as the real process** — here the null drew without the cross-round r_n-exclusion the real process obeys, so it formed configurations the real process forbids (83–87% of null nuclei), inflating it 2.5–4.6× and confounding the z-test.
*   **A result forced by the parameters is not a finding — check whether the simulation could have returned anything else (S-059, Task P):** Task P was recorded for three sessions as "a single extreme super-hub failing is insufficient to cascade at $r=2$ — heavy tails don't bypass the multi-path requirement," and reached an advisor-facing page as a negative *result*. It is arithmetic. The seed was one node, so every neighbour had exactly one failed neighbour against $r=2$: zero solvency failures are possible in round 1 **deterministically, for a single seed of any degree**. The hub's degree of 1555 never enters the calculation; a degree-2 leaf returns the identical answer. The fear channel cannot bridge it for the same reason — the field is $g=a/n$, small *because* $a=1$. **The tell:** the write-up named the hub's degree, its weight, and its fear as though they were experimental conditions, when none of them could affect the outcome. **The check, before calling any null or negative a finding: name the input you would have to change to get a different answer.** If the only such input is one you never varied (here, seed size), the run demonstrated a rule, not a phenomenon. This is the *parameter-forced* sibling of the S-057 **selection-forced** tautology below — same failure, different mechanism, and the S-057 lesson did not prevent it because it was written narrowly about selection rules. Corollary: a recorded quantity that is causally inert (`hub fear = 1.0` on a node that is already the seed) is a strong signal that the setup was described rather than analyzed.
*   **A statement about a rate is not a statement about a level, and the difference is sayable out loud (S-059, Q3 ν):** the ν fit is $\log(\text{width}) = -(1/\nu)\log n + C$ — a claim about the *slope*, i.e. how fast the transition window closes as $n$ grows. It licenses nothing about the window's width at any particular $n$. On this data the two disagree in sign: fear lowers ν from 5.61 to 4.82 (3.4σ, robust), yet at $n=1000$ the $\mu=0.3$ window is **16% wider** than $\mu=0$ at 4.4σ, and the per-$n$ sign flips across the sweep with most cells not significant. "Fear sharpens the tipping point" is true asymptotically and false at the small end. **Before writing a comparative claim from a fitted exponent, print the per-cell values the fit was made from and check whether the raw comparison agrees with the fitted one.** This is the same shape as the earlier "both rows decline ⇒ fear stops mattering" error (there the *ratio* was the invariant, not the level) — quantities in this project are routinely stable in one variable and not another, so every such claim needs the variable named: *constant in n at fixed μ̄*, *steeper in n under fear*, never bare. Related trap: **ν is inverted like τ** — it sits in the denominator, so larger ν means the window shrinks *slower*. Recover it from the exponent, never from memory.
*   **Derive verdict text from the run's own data, not an inherited static string (S-056, Task X):** a wrapper that reuses another analysis script's `main()` inherited a hardcoded `verdict.note` ("γ=+1 cap-affected at every μ̄") that was true for the original run but contradicted the new run's own cap-free verdict. Reuse of machinery must re-derive any human-readable conclusion from the current artifact's computed fields (and assert the strong claim only when the data supports it), or the artifact will contradict itself. Also: when re-expressing a collapse test against a candidate governing variable whose range barely overlaps across conditions, lead with the robust **sign/ordering** of the effect, not the **magnitude** (which is grid/overlap-limited).
